Showcase roadmap

Pine Computer inside other people's products and agents. The story has three parts: in a product, in an agent app, and as a coworker. This page tracks each showcase, the ways in behind them, and the move into PineSandbox.

Which protocol

Lead with MCP. Keep A2A beside it. Build AG-UI next. Park ACP.

No single protocol reaches every app, and the core behind them is already shared, so each extra one is a thin front door. What needs choosing is the order, and what ships around the protocol.

ProtocolPine appears asWho it reachesCall
MCPA tool the app's own agent callsClaude Code, Codex, Cursor, and the tool slot of every coworker appLead. Widest reach, and the app's thinking stays on the app's model.
A2AA remote agent with tasks, questions and filesAgent platforms and frameworks that delegate to other agentsKeep. It fits what Pine is: a long job that can stop and ask. Already built.
AG-UIA bot inside the app, reached by a URLCopilotKit OpenBot, OpenDots, and the frameworks AG-UI already coversBuild next. The bot shape with no install: OpenBot takes any AG-UI endpoint as a Bot.
ACPA bot that takes the app's engine slotOpenMausBot, nightly OpenBot, ZedPark. Built and proven once. The app treats the engine as its language model, which Pine has to refuse.
SDKThe computer inside your own productProducts with a backend: Tavus demo, Drama Studio, the starterThe base. Everything above runs on the published SDKs.

The something else is packaging. A protocol only gets Pine listed. The model still has to choose it, and the person still has to install it. That means a Pine Computer skill: one SKILL.md package that says when to hand work to the computer, shipped with the MCP server. Claude Code, Codex and LobeHub all read the same package. Where an app has its own plugin system, as DeepSeek Harness does, Pine goes in as a plugin for that system, on the same core.

What to learn

Inkbox

A cloud computer plus email, phone and messaging for agents. Close to Pine's ground, and strong on getting installed.

  • It sells per app, not per protocol. The homepage opens with a picker of agent apps, each with one install line. MCP, the skill and the command line sit underneath.
  • The agent signs itself up. A paste-in prompt sends the agent to a signup guide and a docs index written for agents.
  • The agent is reachable. It wakes on a message or a schedule and sleeps when idle. Pine has the lasting computer; a job that starts from an email or a schedule would show it.

LobeHub

An agent workspace with a Skill Store: built-in capabilities, community skills, and MCP integrations side by side.

  • The skill is the unit. A SKILL.md package installs from the store, GitHub, a URL or a ZIP, and can say how to use an MCP server.
  • One package travels. The same skill format is read by Claude Code and Codex, so one Pine skill covers all three.
  • A public listing. Each skill gets a page with an install prompt for agents and command-line steps.

CopilotKit OpenBot

A workspace for AI coworkers, from the makers of AG-UI. It names its slots plainly: AG-UI connects agents, MCP connects tools.

  • A bot is a URL. Any AG-UI endpoint can be a Bot, with an optional authorization header. Simpler than ACP, which needs a process on the person's machine.
  • The computer slot is the wrong door. Its pluggable computer provider expects the app's own model to drive the machine. Pine goes in as a bot or a tool.
  • One small adapter per framework. Its repository carries a folder for each agent framework. Pine's showcases should be as small and as many.
  • Too many tools hurts. One app approval gave a bot 239 tools. Pine's four tools, one of which takes the whole job in words, is the right size.
